# m68kasm 言語仕様（草案 2）

更新: 2026-07-18

これは従来アセンブラの互換構文ではなく、MC68000～MC68030を明示的に記述するための新しい入力言語である。
ここで決める構文は、アセンブラ本体より先にパーサーのテストとして固定する。

## 基本方針

- レジスタは常に利用者が明示する。自動レジスタ割り付けはしない。
- 代数記法でデータレジスタを使うときは、必ず `d0.b`、`d0.w`、`d0.l` のように幅を明記する。
- 代数記法は命令を読みやすくする糖衣構文であり、隠れた最適化や見えない一時レジスタを使わない。
- 1行には区切り記号 `;` で**複数**の命令または文を並べられる。
- コメントは `//` から行末まで。従来の `;` コメントは採用しない。
- エラーは行・列を表示する。マクロ／include元の完全な位置追跡は今後強化する。

```text
d0.w = d1.w + #1 ; d2.w = d0.w + d3.w ; bra.s .next  // 3命令を1行に置く
```

## 手続き

手続きは `[` と `]` で囲む。閉じ角括弧だけなら通常の復帰手続きであり、必要な後処理のあとに
`RTS` を自動出力する。

```text
[update_player
  d0.l = d0.l + #1
]
```

上は概念的に次へ展開される。

```text
update_player:
  addq.l #1,d0
  rts
```

閉じ角括弧を `]/` と書くと、手続きのスコープは閉じるが `RTS` は出力しない。後続コードへの
フォールスルーや、明示的な `jmp` / `rts` を書く手続きに用いる。

```text
[setup_phase
  d0.l = #0
]/
next_phase:
```

## 手続きローカル変数

手続きの先頭では `local` を使ってローカル変数を宣言できる。

```text
[integrate
  local dx: word, dy: word, flags: byte
  dx = d0.w ; dy = d1.w
  d0.w = dx + dy
]
```

ローカル変数がある手続きは `a6` をフレームポインタとして予約し、`link a6,#-size` と対応する
`unlk a6` を自動出力する。`]/` の場合も `unlk` は出力し、`RTS` だけを抑止する。ローカル変数が
ない手続きには `link` / `unlk` を出力しない。

型は当初 `byte`、`word`、`long`、`ptr` を提供する。配置とアラインメントは仕様に固定し、
アセンブラのバージョンで変化させない。

## 構造体

構造体はフィールドのオフセットとサイズを定義する。実行時の隠れたメモリ管理は持たない。

従来型のフィールド宣言に加えて、`.b`、`.w`、`.l`の短縮形を利用できる。`base`を指定した構造体は
代数記法のメモリオペランドとして扱う。

```text
struct base:a0 vector { x.l, y.l, z.l }

[move_vector
  d0.l = vector,x       // move.l 0(a0),d0
  vector,y = d0.l       // move.l d0,4(a0)
]
```

フィールドはbyte境界、word／longはword境界へ配置する。`base`を持たない構造体も宣言できるが、
現プレビューでは`構造体名,フィールド名`形式のロード／ストアには`base`が必要である。
構造体はターゲット間で共有可能だが、X68000やメガドライブの
ハードウェアレジスタ定義は構造体に混ぜず、各ターゲットプロファイルに置く。

## マクロ、複文、ラベルスコープ

引数なし／引数付きの文マクロを定義できる。引数は括弧・波括弧を含む均衡トークン列として扱う。
マクロ本体は展開時に複文となり、呼び出しごとに独立したラベルスコープを作る。

```text
defmacro IDLE = { nop }

defmacro SKIP_ON_NE(BODY) = {
  bne.s macro_end
  BODY
macro_end:
}

[example
  IDLE
  SKIP_ON_NE({ nop ; nop })
]/
```

`{ ... }`は複文であり、ラベルスコープを1段深くする。内側から外側の既知ラベルは参照できる。
内側で定義したラベルは`}`で消え、別の複文では同名ラベルを再利用できる。マクロ展開は最大64段とする。

通常の前方ラベルも同じスコープ規則に従うため、マクロ内では`macro_end:`のような同じ名前を安全に
再利用できる。入れ子のマクロ呼び出しでは、内側の参照は内側のラベル、外側の参照は外側のラベルへ
解決される。未定義ラベルはエラーになる。

## includeと条件アセンブル

`include "相対パス"`は、includeしたファイルを基準に再帰的に読み込む。循環includeはエラーになる。
include内で定義したマクロや構造体は呼び出し側で利用できる。

条件アセンブルは、定数式を括弧で囲む。マクロ引数をフラグとして渡すこともできる。

```text
ifasm (1 + 2 * 3 == 7) {
  defw $1234
} else {
  defw 0
}
```

`ifasm`では数値と定数ラベルからなる式を利用できる。アドレスラベルは配置前には値が決まらないため
利用できない。コマンドラインからの定数定義は今後追加する。

## 定数ラベル

トップレベルで`NAME equ 式`と書くと、64ビット整数の定数ラベルを定義できる。名前の大文字小文字は
区別しない。定義順に依存せず、別の定数ラベルを参照した式も使用できる。

```text
WORD_BYTES equ 2
ROW_WORDS equ SCREEN_WIDTH / WORD_BYTES
SCREEN_WIDTH equ 320
ALIGNMENT equ WORD_BYTES * 4
MASK equ (1 << 16) - 1
```

定数ラベルは代数記法の即値、RAW命令の即値／実効アドレス、分岐、データ定義、`align`、シフト回数、
`ifasm`を含むすべての数値式で利用できる。

```text
d0.l = #MASK
andi.l #MASK,d1.l
lsl.w #WORD_BYTES,d2.w
align ALIGNMENT
defw ROW_WORDS
ifasm (SCREEN_WIDTH >= 320) { defw 1 }
```

定数ラベルはアドレス配置より前に解決するため、定数定義式から手続き名やアドレスラベルは参照できない。
前方の定数ラベルは参照できる。未定義参照、循環参照、同名定数の重複、および手続き／構造体／通常ラベル
との名前競合はエラーになる。値は64ビットで保持し、`.b/.w/.l`などへ出力する時点で範囲検査する。

## 式

数値式は括弧と優先順位を持つ。優先順位は高い順に、単項`+ - ~ !`、`* / %`、`+ -`、
`<< >>`、`< <= > >=`、`== !=`、`&`、`^`、`|`、`&&`、`||`とする。
数値は内部で64ビットとして評価し、`.b`、`.w`、`.l`へ書き込む時点で範囲検査する。

```text
d0.l = #(1 + 2 * 3)
defw ($10 << 2) | 3
```

## データ定義とアライメント

`defb`、`defw`、`defl`はそれぞれbyte、word、longを出力する。`defs`は1バイト文字列を出力する。
`defb`でも文字列を混在できる。文字列は`\\n`、`\\r`、`\\t`、`\\0`、`\\xHH`、`\\"`、`\\\\`を扱う。

```text
defb $12, $34, "OK\\0"
defw 1, 2, 3
defl $12345678
defs "READY"
```

`align 境界[,詰め値]`は現在位置が境界の倍数になるまで1バイト値を出力する。`even`は`align 2,0`
相当である。命令を奇数アドレスへ配置した場合は暗黙補正せずエラーにする。

```text
align 4
align $100, $ff
```

## 代数記法

初期段階で許可するのは、意図が1対1で68000命令列に下げられる代入・加減算・比較・分岐である。

```text
d0.l = #0            // moveq または move.l
d0.w = d1.w          // move.w
d0.l = d1.l + d2.l   // move.l + add.l
d0.w += #1           // addq.w
a0 = &table          // PC相対 lea
```

`d0` のように幅を省略したデータレジスタはエラーにする。同一式に現れるデータレジスタの幅は一致しなければ
ならない。複雑な式を自動で分割して未宣言のレジスタを消費することはしない。必要なら利用者が式を複数文に分け、
使う `d0-d7` / `a0-a6` を指定する。これにより、生成された命令列とレジスタ寿命を常に追跡できる。

## レジスタ契約

手続きは将来、次のような契約を宣言できるようにする。

```text
[render_sprite uses d0-d3,a0-a2 preserves d4-d7,a3-a6
  // ...
]
```

呼出し側と呼出し先の契約違反は、アセンブル時に検出する。DOS/IOCS呼出しは、明示的に記録されるまで
一時レジスタを破壊し得るものとして扱う。

## switch（実装予定）

`switch`は可変個のcase、値の重複検査、default、入れ子のbreakを扱う必要があるため、文字列マクロではなく
専用構文にする。隠れた作業レジスタを作らないよう、初期実装のセレクタは幅付きデータレジスタに限定する。

```text
switch d0.w {
  case 1: { ... ; break }
  case 2, 3: { ... ; break }
  default: { ... }
}
```

初期実装は`CMP`と条件分岐による線形比較とする。ジャンプテーブル版は、破壊するデータ／アドレスレジスタを
構文上で明示する別形式とし、値の密度による暗黙の切替は行わない。`break`は最も内側のswitchを抜け、
フォールスルーは専用の明示文を設ける。

## CPUプロファイル、ラベル、分岐、RAW実効アドレス

機械語生成時に`--cpu 68000|68010|68020|68030`を指定する。省略時は`68000`である。
命令、幅、実効アドレスの可否は選択CPUで検証する。完全な対応表は
[INSTRUCTION_SUPPORT.md](INSTRUCTION_SUPPORT.md)に記載する。
`check`も指定CPUで2パスの機械語生成まで検査するため、構文として読めてもCPUプロファイル外の命令、
不正な実効アドレス、未解決シンボルがあれば失敗する。出力ファイルは作らない。

手続き名と通常ラベルはグローバルシンボルになる。先頭が`.`のラベルは手続き内ローカルである。
複文内の通常ラベルはその複文のローカルシンボルになる。前方参照を許可し、同一スコープの
同名シンボルはエラーにする。通常ラベルに解決されないシンボル参照はエラーになる。

```text
[copy_words
.loop:
  move.w (a0)+,d0.w
  move.w d0.w,(a1)+
  d1.w -= #1
  bne.s .loop
]/
```

分岐は`.s`または`.w`を明示でき、68020以降では`.l`も指定できる。省略時は`.w`とする。
アセンブラは利用者に見えない分岐幅の拡張・短縮を行わない。

RAW命令では、レジスタ直接、アドレス間接、ポストインクリメント、プリデクリメント、16ビット変位、
インデックス、絶対ワード／ロング、PC相対、即値を利用できる。68020以降はスケール、フル拡張ワード、
プリ／ポストインデックスメモリ間接も利用できる。RAW命令でもデータレジスタの幅は`d0.w`のように明示する。

```text
move.l #$00c00000,a0
move.w d0.w,(a0)
move.l table.l,a1
lea table(pc),a2
move.w 4(a0,d1.w),d2.w
move.l 300(a0,d1.l*4),d2.l
move.l ([16,a0,d1.w*2],32),d2.l
move.l ([16,a0],d1.w*2,32),d2.l
```

RAW論理・シフト命令では次の形式を利用できる。

```text
lsl.w #2,d1.w
lsr.l #8,d0.l
lsl.b d2.l,d3.b
lsl.w (a0)
asr.w #8,d0.w
asl.w #1,d1.w
roxr.l d2.l,d3.l
roxl.b d4.l,d5.b
ror.w (a0)
rol.w 4(a1)
andi.l #$0000ffff,d0.l
or.w (a0),d2.w
or.l d3.l,(a1)
add.b d0.b,d1.b
add.w 4(a1),d2.w
add.l (a3)+,d3.l
add.l #$12345678,d4.l
cmp.b d0.b,d1.b
cmp.w 4(a1),d2.w
cmp.l (a3)+,d3.l
cmp.l #$12345678,d4.l
```

`ASL/ASR/LSL/LSR/ROXL/ROXR/ROL/ROR`のレジスタ形式は`.b`、`.w`、`.l`、即値カウントは
1～8である。回数をデータレジスタで指定する場合も幅表記を必須とするが、MC68000はそのレジスタの
下位6ビットを使用するため、回数側の`.b/.w/.l`は同じ機械語になる。1オペランドのメモリ形式は
ワード幅・1ビットだけで、`.w`は省略できる。

`ANDI/ORI/EORI`は即値からデータレジスタまたはメモリ可変実効アドレスへ出力し、CCR/SR専用形式も扱う。
`OR`はデータ実効アドレスからデータレジスタ、またはデータレジスタからメモリ可変実効アドレスの両形式を
扱う。アドレスレジスタを論理演算のオペランドにはできない。

`ADD/SUB/AND/OR`は`<ea>,Dn`と`Dn,<memory>`を扱う。`ADDA/SUBA`、即値、クイック、
拡張付き形式はそれぞれ固有の合法オペランドを検証する。

`CMP.b/.w/.l <ea>,Dn`、`CMPA.w/.l <ea>,An`、`CMPI`、`CMPM`を実装する。
いずれもオペランドを変更せず条件コードだけを更新し、形式ごとの実効アドレスを検証する。

RAWクイック命令は次の形式を利用できる。代数記法のロング即値代入が-128～127なら`MOVEQ`、
加減算の絶対値が1～8なら`ADDQ`または`SUBQ`へ下げる。負の即値は演算方向を反転する。

```text
moveq #7,d0.l
addq.w #8,d1.w
subq.l #1,(a0)
```

MC68000/68010の乗除算はワード形式を使う。68020/68030ではロング形式とレジスタ対も指定できる。
ソースはデータ実効アドレス、出力先はロング幅データレジスタとして明示する。

```text
mulu.w d2.w,d0.l
muls.w (a0),d1.l
divu.w 4(a1),d2.l
divs.w #-2,d3.l
mulu.l (a0),d2.l
muls.l (a0),d1.l:d0.l
divul.l (a0),d3.l:d2.l
```

RAWバイナリの配置アドレスが0以外の場合は`--base-address`を指定する。絶対シンボル参照には
ベースアドレスが加算されるが、PC相対分岐の距離は変化しない。

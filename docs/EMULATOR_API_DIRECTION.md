# XEiJ API・ユーザー操作モードの方針

更新: 2026-07-13

これは将来のXEiJ開発支援改造に対する方針であり、現時点では実装していない。

## 前提

XEiJはこの作業環境での開発専用である。ただしエミュレータそのものは、開発者が画面を見て
手動操作・デバッグできなければならない。自動化APIを追加しても、既存のユーザー操作をAPIへ
置き換えたり、GUIを廃止したりしない。

## 3つの利用モード

| モード | 用途 | ユーザー操作 | API |
| --- | --- | --- | --- |
| GUIモード（既定） | 手動実行・画面確認・デバッグ | XEiJの既存Swing画面を直接操作する | 同じエミュレータコアへ接続できる |
| ヘッドレスモード | CI・自動ビルド確認・記録再生 | 画面は出さない | ローカルAPIで操作する |
| ユーザーコンソールモード | ヘッドレス実行中の観察・介入 | 別プロセスの操作画面から接続する | 同じローカルAPIへ接続する |

ヘッドレスモードは明示指定でのみ起動する。通常の`Run-XEiJ.ps1`は今後もGUIモードを既定とする。
ヘッドレスで起動した場合も、ユーザーコンソールを後から接続できるようにし、状態表示、リセット、
入力、停止、スクリーン取得を行えるようにする。

## APIの最小範囲

初期APIはローカルホストだけに束縛し、外部ネットワークへ公開しない。

```text
GET  /v1/status              実行状態、機種、フレーム数、停止理由
POST /v1/reset               リセット
POST /v1/input               キー・ジョイスティック入力
POST /v1/media/hfs           許可済みホストディレクトリの割当
GET  /v1/screenshot          現在フレームの取得
POST /v1/run                 登録済みのテスト／実行エントリを開始
POST /v1/stop                実行を停止
```

任意のホストコマンド実行、任意パスの読書き、任意のROM／ディスクイメージ指定は初期APIに含めない。
HFSは`src/platform/x68k/build/`などのプロジェクト内許可ディレクトリを既定で読取り専用にする。

## 実装上の境界

- 既存HFSはホストファイル共有に利用できる。APIはHFSの割当を操作してよく、独自のファイル転送形式を
  最初から作らない。
- XEiJの既存TCP/IP端末はRS-232C／コンソール向けなので、制御APIの通信路として流用しない。
- API要求、GUI操作、ユーザーコンソール操作は、単一のエミュレータ実行キューで直列化する。
  GUIスレッドやエミュレーション中のメモリ状態を外部スレッドから直接変更しない。
- ヘッドレスとGUIは別エミュレータを二重起動しない。どちらも同一コアに対する異なる表示・操作面とする。
- 認可は初期段階でもループバック限定に加え、起動時トークンを要求する。ユーザーコンソールはその
  トークンで接続する。

## ライセンス

この改造はローカルの開発専用として扱う。改造版を外部配布する場合は、XEiJの元ライセンスに従い、
無償配布、再コンパイルに必要なソースコードの同梱、ライセンス本文の添付を必須とする。
